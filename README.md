# 听码 · Windows 直播口令输入

点击悬浮“我想要”或按 F8，识别电脑正在播放的直播语音，将明确的纯数字口令填入当前输入框，或提交到已绑定的抖音网页版直播间。每轮最多一次；当前输入框模式不按回车。

默认模型为用户指定的官方 **`qwen-audio-3.0-asr-flash-streaming`**。在软件的“API 设置”中填写自己的 Key，也可以修改完整接口地址、模型和协议。Windows 电脑不需要本地运行大模型，不需要独立显卡。

## 在 Windows 启动

1. 安装 [Python 3.12 的 64 位 Windows 版本](https://www.python.org/downloads/windows/)，保留安装程序中的 Python Launcher（`py`）。建议使用 Windows 10/11 的 x64 电脑。
2. 解压完整项目到有写入权限的文件夹，例如“文档\听码”。不要直接在 ZIP 里运行。
3. 双击 **`启动听码.cmd`**。首次启动会创建环境并下载依赖，需要联网；以后直接启动。
4. 点“API 设置”，填写 Key，点“测试连接”，再“保存设置”。Key 只保留到退出软件，下次需要重新填写。
5. 点“准备系统声音”，打开直播。采集的是 Windows 默认播放设备的声音，直播应使用这个设备输出。
6. 第一次建议勾选“仅预览”，确认识别结果正确。正式使用时取消勾选，先点中目标输入框，再点击悬浮按钮或按 F8。

若使用抖音弹幕发送，按下方步骤选择“抖音网页版弹幕”；无需先点中弹幕框。

再次点击悬浮按钮/F8 可取消本轮；识别时若 Esc 快捷键注册成功，也可以按 Esc 取消。F8 被其他软件占用时，使用悬浮按钮。右键拖动悬浮按钮可移动位置。

每轮最长收音 12 秒，检测到一小段讲话后的约 650 毫秒安静会结束收音。等待结果最长约 35 秒。直播音乐、断续口令、很轻的声音会影响自动断句；未得到明确结果时，重新听一轮。

取消后如果显示“上一轮连接仍在结束”，说明网络握手尚未返回。稍后再试，软件不会积累新的等待连接。

## 抖音网页版：识别后发送弹幕

本版优先接入网页版。软件能核对直播间地址并操作具体弹幕控件；桌面版尚未验证。

1. Windows 安装 Microsoft Edge。在听码的“输出到”中选择 **抖音网页版弹幕**。
2. 粘贴 `https://live.douyin.com/直播间数字编号` 形式的完整链接，点 **打开 Edge**。不支持短分享链接；可先在浏览器打开分享链接，再复制最终直播间地址。
3. 在新打开的专用 Edge 窗口自行登录抖音并播放直播。这个窗口使用独立登录状态，已有普通 Edge 窗口的登录不会直接带入。
4. 填好 API Key、准备系统声音；首次仍建议用“仅预览”检查识别与位数。
5. 取消“仅预览”，勾选 **识别后自动发送一条数字弹幕**。该开关每次启动默认关闭。
6. 保持这个直播间标签页可见、弹幕框为空，点击悬浮 **我想要 / F8**。软件先检查目标，再收音；只有最终识别通过纯数字与位数检查才填入并点击发送。

修改链接后必须再次点“打开 Edge”。不要在识别期间切房、刷新、关闭标签或编辑弹幕框；这些变化会阻止本轮提交。软件只处理自己打开并绑定的标签，不向随意一个前台窗口按回车。每次点击只听一轮，不常驻自动刷弹幕。

发送保护：

- 已有草稿时拒绝开始，不覆盖用户输入；识别中出现草稿也拒绝发送。
- 至少间隔 3 秒；30 秒内相同数字再次提交会被拦截。不会排队等候或延后补发。
- 页面控件找不到、不唯一、不可用或目标已变化时停止。遇到登录、验证码、禁言等提示，请在网页自行处理。
- **“已提交一次，输入框已清空”只说明网页提交后的状态，不代表平台审核通过或所有观众可见。** 软件没有调用私有发送 API，也没有可验证的服务器送达回执。
- 点击后报错或输入框未清空，显示“发送状态不明”并暂停；不会自动重发。检查直播间后，可点“我已检查直播间，解除发送暂停”，再主动开始新一轮。解除暂停本身不发送。
- Esc/F8 可以请求取消。若文字已填入但尚未提交，可能留下数字草稿，请检查；已经提交的弹幕无法通过取消撤回。

专用浏览器登录资料保存在 `%APPDATA%\Tingma\DouyinEdge`，由 Edge 管理；不要把这个目录当源码发给别人。清除登录状态可先关闭听码及专用 Edge，再删除此目录。源码 ZIP 不包含登录资料。

## 申请与填写 API

从用户提供的 [官方模型页](https://www.qianwenai.com/models/qwen-audio-3.0-asr-flash-streaming) 点击“调用 API”，或进入 [千问 AI 的 Key 管理页](https://platform.qianwenai.com/home/api-keys)。按控制台要求开通模型服务与计费权限。Key 不需要发给开发者或粘贴到聊天里。

默认预设对应模型页提供的示例：

| 设置 | 默认值 |
| --- | --- |
| 接口协议 | 千问 Audio 3.0 · 实时语音 |
| 完整 API 地址 | `wss://dashscope.aliyuncs.com/api-ws/v1/inference` |
| 模型名称 | `qwen-audio-3.0-asr-flash-streaming` |
| API Key | 你自己申请的 Key |

**以你的控制台提供的地址为准**：地域、工作空间和 Key 必须匹配。部分账号可能使用带工作空间前缀的地址，可在界面中直接覆盖预设。

另外保留三种兼容选项：

- **百炼 · 实时语音**：Qwen3 Realtime 的 `session.update` / `input_audio_buffer.append` 协议，示例模型 `qwen3-asr-flash-realtime`，地址以 `/api-ws/v1/realtime` 结尾。
- **百炼 · 短音频识别**：完整 HTTPS `/chat/completions` 地址，使用 Qwen `input_audio` 数据格式，示例模型 `qwen3-asr-flash`。
- **自定义 · 标准音频转写**：完整 HTTPS `/audio/transcriptions` 地址，以 multipart 上传 WAV 文件和模型名称，响应应包含 `text`。填入服务商支持该协议的真实模型名。

不同协议不能只靠替换模型名称互换；“自定义”并不代表兼容任意服务商私有接口。流式千问 Audio 3.0 使用 `run-task` / `finish-task` 与二进制 PCM，和 Qwen3 Realtime 不同。

“测试连接”不上传声音。Audio 3.0 测试仅验证 WebSocket 鉴权握手，不证明模型调用成功；HTTP 测试查询同版本的 `/models`，不支持此路由的服务可能无法通过测试，但仍可保存设置尝试识别。真正识别前，请确认服务商的额度和计费规则。

## 纯数字纠错和防误填

**识别结果按数字口令处理：最终仅允许 ASCII `0–9`，共 1–32 位。** `008` 是三位口令，不会变成 `8`。字母模式已移除；小数点、正负号和其他符号不能写入。当前输入框模式按原选区插入/替换，不擅自清空原内容；抖音模式要求弹幕框为空。

| 识别原话 | 处理结果 |
| --- | --- |
| 零零八 / ００８ | `008`，保留前导零 |
| 幺二三 | `123` |
| 两个零 / 2 个 0 | `00` |
| 三个八 | `888` |
| 两个零，八 | `008` |
| 两个零三个八 | `00888` |
| 12 34 / 12，34 | `1234`，按数字口令分段报数合并 |
| 一百零二 | `102`，明确的中文数值转换 |
| 一百二 | 含义不明确，拒绝自动填写 |
| 两个12 / 两个一二 | 重复范围不明确，拒绝自动填写 |
| 12m3 / 两个m / O08 | 拒绝，不删字母凑数字、不猜字母对应数字 |
| 1.2 / -12 / 9.9元 | 拒绝，不把小数、负数或价格变成口令 |
| 不是123，是456 | 拒绝，不从否定或更正表达中擅自选择一个答案 |

处理顺序是：识别已知口令提示语和数字表达 → 判断重复和分隔边界 → 展开明确数字 → 核对位数 → 在写入前再次校验。任何无法完整解释的内容都会拒绝自动填写，不从闲聊中随意抓取数字。

重复只允许一个数字，不能暗中把“两个12”解释成 `112` 或 `1212`。重复后继续报数时，用清晰分隔，例如“两个零，八”；软件不会通过合并或删除重复的数字来“去重”。十个零可按重复读法展开，但仍受设置的最长位数限制。

在主窗口设置最少/最多位数。**已知固定长度时，把两端设成同一个值**，例如六位口令设为 `6 至 6`。长度不符会拒绝，不补零、不截断。升级时自动忽略旧配置中的字母/数值模式，同时保留 API 地址、模型、长度和预览设置。

- 中间识别文字只预览，最终结果通过检查后才填写。
- 取消、超时、迟到或重复的同轮结果不能再次写入；当前输入框模式的不同轮次可填写相同数字，抖音模式另有 30 秒重复保护。
- 当前输入框模式填写前核对目标窗口、控件、内容和选区；核对失败时仅保留有效结果供手动复制。
- 密码框、只读控件、不提供完整 Windows 辅助功能信息的输入框不自动填写。
- 部分直播客户端、网页富文本框或游戏内输入框可能不支持。可以使用“仅预览”和“复制结果”。

下方“试算”可检查上述规则，不调用 API。ASR 把一个数字听成另一个数字时，单靠格式校验无法发现；首次使用先预览，并尽量设置准确位数。

## 声音与配置

使用 WASAPI loopback 获取默认播放设备，转换为 16 kHz 单声道 PCM16；不使用麦克风。准备后音频在本机经过回调，但仅点击后的当前一轮音频进入云端队列，不包含点击前的音频。不会将录音或转写自动保存到文件。系统其他声音也可能被采集，使用时请关闭不需要的播放来源。

接口地址、模型、协议、长度和预览偏好保存到 `%APPDATA%\Tingma\settings.json`；API Key 默认仅在内存中保留。输出目标、直播间链接和自动发送开关不持久化。不得将 Key 写进接口 URL。上传到自填地址的音频由该服务商处理。

如果播放设备改变，关闭软件后重新打开并“准备系统声音”。目标程序和听码建议都以普通权限运行；权限等级不同可能无法访问目标控件。

开发验证命令：

```text
python -m unittest discover -s tests -v
python -m tingma
```

要生成免 Python 启动的程序，请在 **Windows** 中先运行软件完成依赖安装，关闭软件后执行 `scripts\build-windows.cmd`。脚本会运行测试并用 PyInstaller 生成 `dist\Tingma\Tingma.exe`；分发时复制整个 `Tingma` 文件夹。构建产物仍需在目标 Windows 环境验证。

关键文件：`tingma/app.py` 为界面和流程，`tingma/cloud_api.py` 为云端协议，`tingma/windows_audio.py` 为系统声音，`tingma/windows_input.py` 为目标输入保护，`tingma/douyin.py` 为专用 Edge 与弹幕发送保护，`backend/normalizer.py` 为口令纠错。

浏览器依据：[Playwright 的 Edge 通道与独立持久配置](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context)。依赖安装包含驱动，使用本机 Edge，无需额外下载 Chromium；直播网页改版或浏览器升级后，需重新验证控件兼容性。
